# UI modernization route, action, and state inventory

Source baseline: [`02cbc725ac9ddcd950f4400d8355dd78bfcd6c57`](https://github.com/kubeflow/pipelines/tree/02cbc725ac9ddcd950f4400d8355dd78bfcd6c57) for [#14572](https://github.com/kubeflow/pipelines/issues/14572).

This is the current behavior contract for migration. It records source and existing test coverage, not test results or an assertion that every scenario already has coverage. Evidence from executing the baseline belongs in the baseline report. Preserve behavior unless a reviewed modernization change explicitly replaces it.

The baseline uses KFP v2 APIs and native run/task/artifact data. Legacy v1 implementation files present on other branches are not part of this inventory.

## Query and bookmark compatibility

The authoritative list is `QUERY_PARAMS` in [Router](../../src/components/Router.tsx). Preserve these entry points and browser Back/Forward behavior:

- `cloneFromRun`, `cloneFromRecurringRun`: initialize cloning from the relevant resource, preserving runtime config and schedule data. Conflicting run and recurring sources are invalid.
- `experimentId`, `pipelineId`, `pipelineVersionId`: initialize selectors and creation context. Creating an experiment from a pipeline carries its latest version forward.
- `recurring`: initializes recurring creation; `firstRunInExperiment`: first-run entry context.
- `returnTo`: return from run creation only to a safe same-app path; unsafe/external paths are rejected.
- `fromRun`, `fromRecurringRun`: embedded pipeline views; `fromRun` also supplies an existing-run source to run creation.
- `runlist`: comma-separated comparison run IDs, with 2–10 required by the route.
- `task`: native task ID in Run Details query; encoded identity, query-only navigation, removed/unknown task, delayed task ancestry, nested graph fallback, and current canvas selection must work together.
- `executionRedirect`: legacy bookmark guidance (`list` or `detail`), removed when dismissed without clearing other query state.
- `view` is still a declared router query name, but no UI consumer of `QUERY_PARAMS.view` is present in the inspected source at this baseline (the API also has a separate `view` parameter). Do not invent a new meaning as part of presentation migration.

## Migration evidence to attach

Each workflow implementation should identify the route IDs and shared contracts it changes, link the relevant regression tests, and attach representative screenshots or recordings. The following checklist tracks required verification evidence; unchecked items are not claims of observed browser behavior:

- [ ] **Core path:** upload pipeline → inspect/select version → create experiment/run → observe run and task states → logs/artifacts → compare runs.
- [ ] **Lifecycle path:** archive/restore experiment and run; confirm/cancel deletion; retry failed run; terminate running run; verify partial bulk failure.
- [ ] **Recurring path:** pinned and latest-version schedules; clone, enable, disable and delete; manage from experiment; retained metadata when a version is missing.
- [ ] **Navigation path:** fresh hash URL, deployment prefix, Back/Forward, query-only task switch, encoded IDs, legacy redirects and unknown route recovery.
- [ ] **Failure path:** first load and background failure, timeout/unreachable API, 403, 404, 500, empty resources, partial related-resource data, delayed task/artifact data, retry recovery.
- [ ] **Context path:** standalone and central-dashboard embedding, namespace switch, private/shared pipelines, relevant pipeline stores, local-storage unavailable; feature flag variants until deliberately retired.
- [ ] **Presentation path:** keyboard-only navigation and action completion, focus return from dialogs/panels, large tables/long names, narrow windows, graph and log scrolling, zoomed text, and new theme states.

## Gaps and implementation decisions

- **Permission coverage:** current tests cover selected authorization failures but do not establish a complete read-only/forbidden browser matrix for every mutation. Add explicit denied-read and denied-write cases for each workflow when migrating it; retain server error handling.
- **Route coverage is not full browser coverage:** component/unit tests and existing `*.integration.test.tsx` files are useful anchors. Their presence does not establish visual, focus, iframe, live-cluster, or cross-browser parity.
- **Secondary surfaces need design application:** archive screens, upload variants, experiment recurring-run manager, feature flags, not-found and failure states remain in scope even where the handoff has no separate mockup. Use the shared design components while preserving their actions.
- **New theme behavior needs new evidence:** current shell styling is not a system/light/dark theme contract. Theme persistence, contrast and graph/viewer/editor behavior must be verified with the new foundation.
- **Existing limitations are separate from parity:** for example, the experiment recurring count fetches only its current first page, and NewRunV2 has a TODO for more actionable parameter/root validation messages. Document deliberate changes and add tests; do not silently make the redesign responsible for unrelated backend behavior.
- **Refresh semantics vary:** some older table screens replace rows on an initial load failure; newer native artifact/run/task surfaces retain cached data on refresh failure. Preserve established recovery guarantees, and make any consistency improvement explicit.
