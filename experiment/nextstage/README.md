# Post-smoke paired coordinator integration

Separate candidate; the previously prepared smoke files are unchanged. No live
operations or publication were performed. Run from this directory with
`python3 coordinator.py validate --config CONFIG --out OUTPUT`, then `arm --index 1` only
after smoke readiness and review. Existing coordinator config additionally
requires absolute `scheduled_binary` and `fixture_evaluator` paths.

Each arm now performs actual generated-client recurring lifecycle before setting
the common future start; all four tenants must create, observe a succeeded child,
disable and confirm the schedule. The same stage runs after load/drain. These
are explicitly outside the measurement clock and do not prove SWF under load.
The coordinator captures exact container UID/restart/ready state before and after
load and rejects replacement/restarts as health evidence. It captures terminal
GetRun under each owner's token and invokes the fixture evaluator for every
recorded run. Accepted IDs remain preserved; no automatic deletion or write retry.

`acceptance.py` includes strict classification and recovery evaluators. They need
actual response-header observations mapped to captured Limited policies, and full
60-second raw successful latency windows; configured UIDs or averaged percentile
values cannot pass. These inputs are NOT yet emitted by the source image/current
observer, so those gates remain explicitly missing rather than fabricated.

Remaining blockers to full acceptance:

- Optional `artifact_gateway` plus `artifact_capture_helper` wires the owner
  capture helper. It requires a REAL authenticated gateway that validates bearer
  and injects trusted identity. Existing direct frontend forward only trusts
  kubeflow-userid and cannot fulfill this; no spoofed identity header or admin
  download is allowed. Without gateway the oneof evaluator fails explicitly.
- Coordinator now runs separate authorization probes before, during sustained
  load (seconds130..300), and after drain: cross-tenant CreateRun/GetRun and
  invalid-token GetRun must return401/403. No write retry; unexpected accepted
  IDs retained. Each denied unique name is absent from two bounded owner
  listings two seconds apart. These prove observed absence, not arbitrary
  future absence; ambiguous/truncated listing fails. During worker failure
  cancels workload and observer. Probe overhead is present identically in arms.
- Actual KFP transport APF headers for all five client paths are unavailable;
  supplied FlowSchema IDs alone cannot satisfy classification.
- Recovery evaluator still needs per-second original successful latencies and
  calibrated quiet baseline from the observer/workload; no summary substitution.
- Direct etcd latency/health, observed server termination for no-deadline/client
  disconnect, supported minimum Kubernetes and APF-disabled fallback remain.
- Tokens are provisioned for1h; six long arms require controlled token renewal
  before each arm. Validation requires45minutes remaining expiry.
- Run individual indexed arms1..6 into fresh directories. Monolithic `run` is
  disabled. A45minute process watchdog preserves partial evidence and cancels
  owned children; it does not prove server-side accepted runs terminated.
  Recurring preflight budgets120seconds per tenant, before and after measurement.

Offline verification: ten evidence-rejection regression tests and Python syntax
checks pass. This is a runnable integration candidate, not a completed acceptance
suite. Existing evaluator continues to return `default_change_supported:false`.

The server-evidence sibling now supplies projected audit+HTTP joins.
`acceptance.audit_classification` validates complete nonambiguous joins, actual
KFP caller, shared Limited priority, and TokenReview/SAR/Argo/SWF/core path
coverage. This requires audit+JSONv3 configuration before cluster creation and
still does not identify KFP tenants or correlate outgoing attempts to RPCs.
No fabricated joined file is generated by the coordinator.

## First hosted pair: obtain measurements without asserting acceptance

`hosted-pair.yml` reuses the smoke bundle and additionally needs
`experiment/nextstage`, `experiment/workload/{main.go,scheduled/main.go}`, and
`experiment/observer/main.go`. It runs one exploratory20/-1 pair, not all three
required repetitions. Later repetitions must use the same frozen controls and
counterbalanced indices3..6. Root publishes only after review.

`prepare_pair.py` guards cluster ownership, creates a namespace-scoped ConfigMap
competitor with only get/list/update, records its actual APF headers and stock
policy snapshots, renews experiment tokens, and freezes rates. It does NOT
claim the supplied candidate KFP FlowSchema is observed KFP traffic. If actual
KFP classification differs, shared-priority fairness is inconclusive. No APF
policy or server-seat manipulation is performed. If these bounded rates do not
produce queueing, report overload not demonstrated.

`measurement_only:true` explicitly permits collecting measurements before the
full prewarm attestation; it does not bypass any acceptance gate. Workflows still
must run and authorization probes still stop on wrong/ambiguous results. Missing
artifact gateway produces failed semantic evidence rather than an invented
pass. Scheduled stage permits300seconds per tenant under the whole-arm45minute
watchdog. A timeout preserves evidence and cancels owned processes.

Provisioning output is captured separately; only sanitized arm evidence is
uploaded. `apf-pair-private` contains tokens and must never be uploaded.

## Prepublication runtime review

The paired workflow uses the already approved exact smoke branch. Workload,
observer and scheduled-client CLI flags match the coordinator, and all three
build against the source dependency module. Observer Context JSON tag was fixed
and regression-tested. Runtime image validation accepts a CRI config digest
directly or verifies containerd manifest/index bytes and their config digest
against the pinned Docker-save identity; string suffix comparison is not used.
The node inspected is restricted to the owned Kind control-plane.

Every arm now writes acceptance.json plus a root acceptance.json. Both always
keep acceptance_complete/default_change_supported false. Failing baseline
semantic assertions remain explicit; exploratory measurements cannot authorize
a production default change. Actual classification, complete no-deadline attempt
cessation and remaining predeclared safety gates are still incomplete.
